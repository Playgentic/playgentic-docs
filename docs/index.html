Getting started

playgentic is a zero-dependency CLI that scaffolds a Playwright-BDD suite pre-wired for a Claude Code agent pipeline that writes and heals your tests. This page gets you from nothing to a running suite plus a first agent-generated scenario.

Requirements Node >= 22.22.1 and npm. For the agent pipeline: Claude Code, GitHub Copilot CLI or Codex. The agents plugin brings its own playwright-test MCP server, which runs from the suite's Playwright.

1 · Scaffold a suite

Create a new suite in its own folder:

$ npx playgentic init my-suite
$ cd my-suite

Adding tests to an existing project instead? Run it in place — it merges into your package.json (adds scripts + devDeps, never clobbers yours):

$ cd my-existing-app
$ npx playgentic init .

2 · Point it at your app

Copy the env template and set TARGET_URL to the app under test. This becomes Playwright's baseURL, so steps navigate with relative paths.

$ cp .env.example .env
# .env
TARGET_URL = https://your-app.example.com
# Optional auth creds — read via the world fixture, never hardcoded in features
# STANDARD_USER = 
# STANDARD_PASS =

Credentials belong in .env (or CI secrets), not in .feature files. See Working off the template → Credentials.

3 · Install browsers & run

Install the Playwright browsers, generate the step wiki, and run the example scenario.

$ npx playwright install
$ npm run wiki   # index steps + page objects into .playgentic/wiki/
$ npm test       # run the example scenario

The example feature has one scenario per device. Each device project only runs scenarios tagged with its name (@desktop, @mobile), so tag every scenario you write; untagged ones don't run. See The Playwright config.

See Playwright → Browsers for browser/OS specifics.

To run the suite in GitHub Actions, add a TARGET_URL repository secret. The scaffold's playwright.yml workflow picks it up. See Repo setup → CI.

4 · Let the agents write coverage

Wire the playgentic agents for your harness, either at init time with --agents or later from the suite root:

$ npx playgentic agents claude,copilot,codex   # any subset, or "all"

That registers and enables the plugin, but each person still installs it once. In Claude Code, trust the folder and accept the plugin install prompt, or run:

$ claude plugin install playgentic@playgentic --scope project

Restart Claude Code afterwards. Copilot and Codex have their own one-time step, printed by the command and listed in Architecture → Agent harness.

Then run the author-tests skill. It cuts a feature branch, agrees acceptance criteria with you, explores the live app, builds and runs tests in this suite's conventions, has an auditor review them, and commits only test files.

# Claude Code
> /playgentic:author-tests --gen  cover coupon codes at checkout
> /playgentic:author-tests --heal the login scenario fails after the redesign

How the wiring works: Architecture → Agent harness.

5 · Keep agents up to date

Nothing to do. The agents aren't copied into your repo; they update through each harness's plugin marketplace. To pin a release, re-run with --agents-ref <tag>.
